# Вливание выпусков JugglucoNG — порядок для чата

**Когда.** Письмо GitHub о красном запуске `RUS sync`: задание «Выпуск X ждёт вливания» (это напоминание) или что-то
красное (сбой). Берём только их выпуски без пометки «пред-выпуск»; другую точку — только по слову владельца.

**1. Прочитать отчёт** — страница утреннего запуска (`gh run list -w rus-sync.yml`, итог `report`, файл
`sync-report`): сводка, флаги риска (датчик и тревоги — первыми), эталоны, их CI, их Issues за 7 дней, их новые
функции против `rus/CHANGES.md` и открытых строк `неудобства-jugglucong.md` (ТЗ 3.4).

**2. Влить** (Git Bash, из `code\`):
```
bash rus/sync-merge.sh prepare --decision "влить: <почему>" --minutes <сколько разбирал>
bash rus/sync-merge.sh finish <номер PR>
```
`prepare`: ветка `sync/<выпуск>`, слияние, проверки, строка в `rus/SYNC-LOG.md`, PR с отчётом. `finish`: ждёт
проверку PR, вливает слиянием (без squash и rebase), выключает их новые задачи из отчёта. Нужный коммит libjuice не
в нашей копии (раздел 11) — сначала `gh repo sync lbarmen/libjuice`.

**3. Владельцу — 3–5 строк** «что поменялось для тебя»: датчик, тревоги, часы, Nightscout, что заметно в
приложении; что проверить на телефоне до установки (флаги риска, ТЗ 3.6). Кандидат на телефон — не раньше 7 дней
от выпуска.

**Красное — что делать**
- конфликт — решить файлы руками (врезки — по `rus/HOOKS.md`), `git add`, `git commit --no-edit`, затем
  `prepare-after-conflict --decision … --minutes … --conflicts N`; `rerere` запомнит решение;
- наша сборка (`check-apk`, наследование `rus` от их `release`) — автор поменял сборку: чинить в наших файлах;
- их тесты — красные ли они и у автора (раздел 13)? Да — не наша вина, решает владелец; нет — разбирать;
- эталоны тревог — таблица разницы в отчёте. Решения поменялись по их задумке (PR в разделе 3) — принять:
  `gh run download <запуск> -n sync-tests`, скопировать `Common/build/rus-golden/actual/*.csv` в
  `rus/golden/expected/` на ветке `sync/…`, в строке SYNC-LOG — «эталоны обновлены: <почему>»; не ясно — владельцу;
- выпуск сломан у автора и его пропускаем — только по слову владельца: переменная `RUS_SYNC_SKIP=<метка>`
  (`gh variable set`), напоминание молчит до следующего выпуска.

**Раз в месяц** — `python3 rus/juggluco-summary.py` (сводка Juggluco): перенос — только правка датчика,
тревог или часов, которой нет в JugglucoNG, и по слову владельца.

Красный PR можно влить только через обход набора правил «только через PR» и только по слову владельца.
